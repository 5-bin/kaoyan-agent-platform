# 验证记录

验证日期：2026-11-07。验证环境：Windows、Python 3.13.9、内置 Chromium 浏览器。

## 自动化测试

执行 `python -m unittest discover -s tests -v`，12 项测试全部通过。

- 金额精度：0.10 + 0.20 = 0.30；拒绝零、负数、超过两位的小数、非数值和非有限值。
- 日期与类别校验：拒绝不存在的日期、错误格式和与收支类型不匹配的类别。
- 新增、编辑、删除后重新实例化服务，验证 JSON 持久化结果。
- 日期和金额区间包含边界；多个条件取交集；明细与汇总一致。
- 损坏 JSON、重复 ID 会阻止读取，保留原文件。
- 模拟替换文件失败，确认磁盘和内存记录不变，临时文件被清理。
- 外部修改不会被当前服务覆盖。
- HTTP 增删改查、静态资源、错误输入、缺失记录与访问限制。

另通过 `node --check static/app.js` 与 Python 编译检查。Node.js 仅用于开发验证，运行软件不需要安装。

## 浏览器操作验证

使用 `.qa/browser.json` 独立测试账本，未写入正式账本。

- 空状态显示正常。
- 新增 25.50 元餐饮支出与 5,000 元工资收入，结余 4,974.50 元。
- 新增 6 元交通支出，将餐饮金额改为 28.50 元，按餐饮筛选时仅展示并统计该记录。
- 重置筛选后可查看所有记录；删除弹窗可取消，也可确认删除。
- 删除交通记录后刷新页面，收入 5,000 元、支出 28.50 元、结余 4,971.50 元，删除结果保留。
- 手机视口 390 × 844 下完成新增记录，页面无整体横向溢出；明细表在自身容器内横向滚动。
- 最终截图含四笔演示账目：收入 5,000 元，支出 124.40 元，结余 4,875.60 元。
- 浏览器捕获的错误日志为空。截图保存在 `docs/screenshots/`。
