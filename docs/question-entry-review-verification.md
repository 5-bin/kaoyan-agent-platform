业务与字段契约以[搭建文档7.2.1](../考研Agent平台搭建文档.md#721-issue-11题目录入与来源审核契约)为准，本页记录验证证据与部署边界。

## 本次交付及兼容性

- 管理员可录入单选题及来源、使用权限说明，查看完整详情与待审核分页，修改未发布题，通过或驳回题目。学生不能调用管理接口。
- 新题仅待审核，通过且启用后才进入学生题池。旧题来源缺失不伪造、不批量修改已发布状态；不完整的旧待审核题须先补充再通过。
- POST／PUT从实体入参收紧为专用白名单DTO；POST不接受版本，PUT只接受必填预期version，下一版本仍由服务端生成；审核人、发布状态等客户端字段均拒绝；成功返回已保存的管理题目。前端同时适配，旧管理客户端需更新。
- 题目审核使用独立DTO，必须发送管理员实际读取的`version`。旧的仅含`status/comment`的题目审核请求需升级；资料审核DTO不变。
- 题目修改、审核及启停使用数据库行锁；PUT修改必须发送读取时的version，过期版本、重复审核或重复启停返回409。成功修改、审核和启停都会使version加一。修改仅允许未发布／驳回题，修改后版本增加并重新待审核。已发布题禁止原地修改，完整不可变版本发布及审核事件历史留待后续建设。
- 管理页可停用／重新启用APPROVED题目，专用接口为`PUT /api/questions/admin/{id}/active`，请求`{active:0|1,version}`。保留来源、审核及历史数据，不触发统计重算。仅六个来源字段全为NULL的旧已审题可按原审核结果恢复，来源仍待补充；部分缺失题目恢复失败。
- 学生白名单DTO、Java判分与历史作答快照、Python协议保持不变。来源定位按文本展示，不直接执行HTML或打开外部地址。
- 使用权限说明属于登记信息，仍需人工核验实际授权，不等于系统已经确认版权。测试中的真题元数据是工程夹具，不是真实真题内容或许可证据。

## V9迁移与#5协调

脚本：`kaoyan-B/src/main/resources/db/V9__question_source.sql`，只在`question`增加六个可空来源列。旧题、审核状态和历史作答均保留；旧字段为NULL表示来源未登记。

本次**没有执行日常MySQL迁移**。交付前由数据库负责人协调#5，确定目标库、备份与可恢复性、维护窗口及迁移执行记录；先在可丢弃的独立MySQL验收库验证，再安排业务库操作。

迁移前可人工执行以下只读核对，不输出凭证或题目正文：

```sql
SELECT DATABASE();
SELECT column_name, data_type, is_nullable, character_maximum_length
FROM information_schema.columns
WHERE table_schema = DATABASE() AND table_name = 'question'
  AND column_name IN ('source_type', 'source_name', 'source_locator',
                      'source_year', 'source_question_no', 'permission_note');
SELECT COUNT(*) AS question_count FROM question;
SELECT COUNT(*) AS attempt_count FROM practice_record;
```

已有库先核对V7/V8及其执行记录；仅在V9尚未应用且不存在同名列冲突时，按受控流程执行一次V9，再启动新版Java。六列已存在时核对类型／长度／可空性和迁移记录，不要直接重跑。全新可丢弃库才可按V1→V7→V8→V9初始化；V1含DROP，不得用于修复已有库；V4删题种子不得用于扩充正式题库。

V9有六条独立DDL，MySQL可能逐条提交。中途失败不可假定已全部回滚：停止后续发布，检查现存列和错误，由负责人审阅后仅补执行未完成的语句，不盲目重跑整个脚本。迁移后核对六列及前后行数，确认旧快照未被覆盖，并在隔离账号完成录题／审核／刷题联调。H2兼容模式测试不替代真实MySQL验收。

应用回退时可保留新增列和已录入数据，再部署经确认兼容的旧应用；不要删除列、清空题目或重跑V1作为回退。恢复旧管理客户端时仍须评估其实体写入和缺少审核版本校验的风险。

## 真实MySQL环境的后续验收步骤（未运行）

1. 在独立验收库核对并执行所需迁移，使用受控授权的ADMIN账号；公开注册不授予管理员权限。
2. 打开`/admin/questions`，录入一条有明确自编记录与权限说明的题；刷新后按返回的ID查看，核对内容和来源持久化。
3. 学生账号不可访问管理接口、不可抽到该待审题；管理员核对后通过，学生方可抽取并由Java判分。
4. 再录入一题并驳回，确认仍不可抽；补充修改后重新待审、版本增加，重新审核。保留旧详情时提交审核应409，刷新详情后再操作。
5. 核对缺少来源／权限或真题年份／原题号返回400，伪造审核身份被拒绝，已发布题PUT返回409；既有历史作答回顾不受新来源列影响。
6. 记录迁移与联调证据后，再由审核人确认功能、来源规则和使用许可。未完成这些步骤不能声称正式数据库部署已验收。
