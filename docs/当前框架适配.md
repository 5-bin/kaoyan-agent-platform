## 修改与当前契约

- 运行入口：补齐 Maven Wrapper、可选后端开发配置模板、统一环境示例和仅首次生成凭证的脚本。CI 指向三个新目录，移除已不存在的旧脚本调用，并加入新框架HTTP检查。显式配置Lombok注解处理并使用1.18.42；JDK25支持依据见[Lombok变更记录](https://projectlombok.org/changelog)，Java编译目标保持17。
- 配置：Java/Python 默认端口统一为 8001。内部凭证、JWT 密钥必须显式提供；清除代码中的固定凭证和数据库密码。MySQL、Redis、OSS 读取环境，兼容已有本地配置覆盖；OSS 未配置不阻止启动，上传返回 503。取消允许循环依赖的开关。
- 会话：JWT显式使用文档要求的HS256，access token 默认60分钟；Redis保存撤销标记及剩余有效时间；验签核对issuer，每次请求重新检查数据库中的账号状态和角色。Redis是运行依赖，不能把无 Redis 的配置描述为已支持的退出机制。登录接口当前只签发access token，前端刷新令牌字段改为可选。
- 任务入参：保留 `KNOWLEDGE_QA`、`SCHOOL_RECOMMEND`、`PRACTICE_SUMMARY`、`CHAT`。前三种文本任务中的非总结类型及 CHAT 仅接受 `input.query`，非空且最多8000字符；总结仅接受 `input.sessionId`，最长64字符。未知字段、未知类型和格式错误拒绝，不创建任务、不调用Agent。
- 总结上下文：先按当前账号和批次查询，空集合返回404；过滤无效判分后没有记录或仍有未答返回409。对错题编号由Java计算，不接受浏览器提交的用户或题目上下文。Python仅查询审核通过且启用的题目，缺题则失败，不用缺失资料生成成功总结。当前仍查现行题表，不宣称历史版本快照已实现。
- 任务保存：先保存RUNNING，远程调用不持有数据库事务；校验响应taskId、SUCCESS/FAILED状态与非空结果对象；故障保存FAILED及统一简短原因。恢复每账号每UTC日30项、每分钟6项的任务配额，检查与落库串行，模型调用在锁外；通过环境可调整但必须为正数。配额使用持久任务计数，FAILED同样计入，非法请求不创建记录；启动时将遗留RUNNING更新为FAILED。任务历史返回数据库实际总数，跨账号详情统一404。任务／题目审核／资料管理的分页统一接收前端pageNum/pageSize，兼容旧page/size。
- Python边界：内部认证失败返回HTTP401；类型、任务编号、非空文本、重复或非法题目编号、额外字段由Pydantic校验；模型异常不向响应或应用日志输出原始详情。缺少模型密钥时健康接口可用，任务失败。
- 证据边界：当前没有检索资料集合，模型返回非空references会被拒绝；已调整提示词明确不生成假引用。练习总结中的题目编号须属于本次授权集合。知识问答仍属无检索模型回答，院校推荐仍缺核验数据，不能宣传为正式RAG或可靠招生建议。
- 超时：模型30秒、完整Python任务40秒、Java读取45秒、浏览器55秒。移除模型适配层及SDK自动重试，避免一次点击产生多次自动重试费用。恢复单Python实例每UTC日100次模型尝试上限，失败请求同样计入；线程锁保证并发不越限，UTC换日和进程重启重置。该计数不是跨重启的账单硬限额。CHAT的意图路由和回答是两次显式调用，分别计数并受同一40秒预算约束。页面超时提示先查历史。
- 前端：补齐任务页面路由和菜单，修复TypeScript工程引用及审核列表分页对象的类型错误；任务历史支持分页并显示失败原因；请求绑定发出时的令牌，账号变化后丢弃迟到成功和401响应；退出先调用服务端撤销。损坏的用户资料缓存不会阻止应用初始化。
- 正式推荐：`POST /api/recommends/generate` 原先任取前五所院校写入个人记录，现返回501且不写占位数据。实验性SCHOOL_RECOMMEND任务仍可调用模型；正式候选筛选和可核验推荐快照待接入。

响应继续使用当前框架的 `{code,message,data}`，业务任务状态继续为RUNNING/SUCCESS/FAILED；未迁移成旧设计的四终态协议。新增正式领域工作流前需要统一新协议、保存结构及页面。
