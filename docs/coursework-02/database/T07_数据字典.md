## 1. 范围、读法与来源


本文描述源码可推出的结构，不代表任何本地或线上库已执行迁移。本次没有连接数据库、执行SQL或启动服务。

28表 = V1的10 + V10的3 + V11的2 + V12的2 + V13的10 + V14的1；V7/V8/V9/V15只加列或约束。测试H2 schema、fixture_*、collection_import_record等导入维护辅助表、Redis及Qdrant不计入本次按迁移定义的28表。

SQL类型、长度、UNSIGNED、可空及DEFAULT以迁移原文为准。“未显式指定（隐式NULL）”表示可空但未写DEFAULT；主键隐含NOT NULL。整数业务标志不自动具备0/1约束。

键栏PK主键、UK唯一键、IX普通索引；(1/2)表示复合键中的列序，而非独立唯一。完整顺序及约束原文列在各表之后。行内UNIQUE未显式命名的约束不虚构索引名。业务含义中的“逻辑关联”不是物理外键，只有V14的fk_admission_detail声明FOREIGN KEY。

V1和V14显式指定InnoDB/utf8mb4；V10—V13未在建表尾指定引擎、字符集或排序规则，需要T06核验目标库默认值。

时间混用DATETIME、TIMESTAMP和DATETIME(6)。V1多数updated_at带ON UPDATE；V10—V12仅DEFAULT CURRENT_TIMESTAMP，由代码显式维护更新；V13多数时间由Java传入，learning_blueprint.created_at精度为6。学习闭环代码用Asia/Shanghai，其他LocalDateTime及数据库会话时区另核验，不宣称全库统一UTC。

## 4. JSON专项核对


原生JSON由MySQL检查语法，不自动校验业务字段；LONGTEXT仅存序列化文本，由Java检查。Task.inputPayload/resultPayload和PracticeRecord.questionSnapshot使用Map<String,Object>、JacksonTypeHandler及autoResultMap=true。

大多数其他JSON对象经ChatRepository.encode/object处理；rows将下划线转驼峰并去掉_json后缀，如data_json→data、config_json→config。它按对象解析，V14的sources_json为数组，由SchoolAdmissionMetrics专用ObjectMapper按List<Source>读取，不能混用。

| 列 | 实际存储 | 内容及校验 |
| --- | --- | --- |
| `task.input_payload` | `JSON` | 按任务保存query、preferences、learningSnapshot、conversationId等输入对象；可因隐私清理置NULL。 |

## 5. 与T06／T10统一的边界


1. V7快照、V8软删除、V9来源六列、V15学位类型全部合入字典；V13/V14新增表全部保留。不能以V1或测试schema替代累计结构。
2. 除V14外是逻辑引用。V1用户/题目/作答ID多为BIGINT UNSIGNED，V10—V13关联ID多有符号；practice_session.id容量64而practice_record.session_id容量36，当前生成34字符可兼容；设置表任务指针64而task.id36。ER可以画业务关系，不补写不存在的FOREIGN KEY，也不宣称类型完全相同。

4. recommend_record保留但新推荐走task；study_stat仍由旧批次提交经accumulate写入，但当前统计读取有效practice_record、不读本表，两张兼容表仍计入28表。
5. 已提交未必已判分，未答不算错题；独立、提示辅助、未知旧样本分开。learning_event.lease_until当前仅结构保留，worker不用。
