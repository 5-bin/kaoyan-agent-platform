## 可用入口与限制

- 服务启动后可在`/schools`测试省份、层次、专业名称筛选和详情页。示例：北京＋985＋“计算机”，数据库查询命中1所虚构院校；6校专业外键关联均完整。
- 题目在`/admin/questions`的待审核列表，资料在`/admin/documents`的待审核列表。需由管理员核对题干、答案、解析和来源后，通过正常审核接口发布，才能用于学生刷题和资料浏览。
- 当前数据库只有学生账号，没有管理员。脚本没有自动提权或创建管理员；管理页面暂不能由当前学生账号访问。管理员账号的受控配置需要另行明确授权。
- 这批记录不会自动成为Agent检索资料。当前Agent独立读取版本化语料；“条件推荐”也不读取这些虚构院校表记录。真实DeepSeek已通过的两轮测试见[模型验证记录](deepseek-verification-2026-10-22.md)。
- 当前聊天与个人文档表仍待V10/V11迁移；本次补数据没有执行迁移、启动服务或浏览器验收。

## 数据文件与重复执行

测试夹具：[local-test-data.json](../scripts/fixtures/local-test-data.json)。批次标记：`local-test-data-v1-20261022`。来源定位指向夹具文件与题目code，供核对和后续整理。

执行脚本：[seed-local-test-data.py](../scripts/seed-local-test-data.py)。从本项目根目录执行：

```bash
# 只校验夹具并预览，不连接数据库。
.cache/chat-venv/bin/python scripts/seed-local-test-data.py

# 在明确授权写入时使用：先备份根.env配置的本机数据库，再事务插入。
.cache/chat-venv/bin/python scripts/seed-local-test-data.py --apply
```

路径`.cache/chat-venv`是当前本机环境，其他机器需使用安装了项目依赖的Python。脚本仅接受回环数据库地址，拒绝缺少必要表或V9字段的环境；不会执行历史种子或V1建库脚本。

脚本按测试题来源、资料标题、虚构院校名称及专业年份组合识别已有记录。重复执行只补缺项，不更新已存在记录，因此不会覆盖后续人工编辑和审核。数据库锁用于避免同脚本并发插入；新增记录使用数据库自增主键。备份失败时不插入，SQL执行失败时未提交事务随连接关闭回滚。
